# JBIT plan

## Goal
Make the headless run honest about progress and close the commit-gate gap it exposed, released as 0.16.0. In a headless run (`claude -p`) neither Sonnet nor Opus writes a progress note between stages, whatever the rules, a reminder or a refusal say ([0.15.0 evidence](plans/2026-11-14-headless-rules/evidence/stage-3/report.md)); the user decided the note isn't required there, and the final report covers each stage. The same runs closed stages with one Bash line that ticks the plan and commits, which the commit gates (checks ticked, evidence present) never see, since they read the pending diff before the command runs. Done means: the rules and the stage-closing reminder ask for the note between stages only when someone reads along, and say a headless run leaves it to the final report, while interactive runs keep it; under autopilot a Bash line that writes the plan file and commits in one go is refused before it runs, and a close the pre-run check still misses is checked against the commit it landed in — failing its checks or evidence, it isn't announced and Claude is told to reopen the stage; the `progress-note` eval grades the final report headless; suite, docs check and validate green; committed on main.
