# JBIT plan

## Goal
Cut JBIT down to what still earns its place on today's models, and ship it as 1.0.0. Keep the plan file (`## Now`, stages with observable checks, dated decisions, archive), the evidence folder, and the judgement habits that changed outcomes in the 2026-11-17 ablation ([research](research/jbit-ablation.md)). Hand the rest to Claude Code: model and effort per role go in agent files, review goes to `/code-review` and `/security-review`, outward safety goes to permission modes and the sandbox. The hook keeps two jobs: putting `## Now` in front of Claude, and the secret guard on commits. It's for the user's own projects, eVelo first. Done when the plugin has role agents, short `plan`, `stage`, `verify`, `resume`, `autopilot` and `charter` skills (no `approve`, `fix` or `review`), a hook of those two jobs with its tests, docs and evals to match, version 1.0.0, and a re-run of the eval subset with no case that changed outcome scoring below 0.18.1's run.

## Decisions
- 2026-11-17 · Cut JBIT down rather than drop it or keep it whole — the user, after the review and ablation in this session ([research](research/jbit-ablation.md)): the plan and evidence discipline helps most on large, multi-session projects like eVelo; the holds, approval grammar, Agents and Models machinery and outward regex cost more than they returned, and the last plan only fixed their clash with worktrees.
- 2026-11-17 · The hook keeps only the `## Now` section and the secret guard — the user's pick. The stage-close commit gate and autopilot continuation go: the evidence rule and running stages in a row become skill instructions, and continuing across turns uses `/loop` or the user's go.
- 2026-11-17 · `charter` stays as a plain skill, with no hook checking the roadmap table or milestone ticks — the user's pick.
- 2026-11-17 · Ship as 1.0.0, replacing the plugin in place — the user's pick. 0.18.1 stays in git history. Old `Mode:`, `Agents:` and `Models:` lines in existing plans (eVelo's) are left alone and ignored.
- 2026-11-17 · Model and effort per role come from agent files, not a plan line: the plugin ships `builder`, `reviewer`, `verifier` and `researcher` without `model` or `effort`, and the user overrides a role with a same-named file in the project's `.claude/agents/` or their own `~/.claude/agents/`. Skills never pass `model` or `effort` on the Agent call, because a call's values beat the file's and would defeat the override. A same-named file replaces the whole definition, so an override is a copy with two fields changed ([research](research/subagent-model-effort.md)).
- 2026-11-17 · Agents: balanced for this plan — the user's pick, over the `wide` line carried from the last plan.
- 2026-11-17 · Agents: wide for the autopilot run — the user's pick in their command ("Jbit autopilot wide"), replacing balanced.
- 2026-11-17 · (unattended) Skills start a role as `builder` when the session's agent list has it, else as `jbit:builder`: stage 1's runs show a project `builder.md` overrides only the bare name, and the bare name doesn't resolve without one ([evidence](evidence/stage-1/report.md)). Stage 2's skills follow this.
- 2026-11-17 · (unattended) Autopilot without the hook's levels: it runs the remaining stages in a row, makes judgement calls inside the plan's intent itself and logs them dated as `(autopilot)`, and stops for the user only when a check still fails after three fix rounds, a builder's report and the evidence disagree, the Goal or scope would change, or the next step is outward or hard to undo (which Claude Code's permission modes also gate). Why: the plan drops the Mode levels and approval grammar, and these are the stops that protect the user without them.
- 2026-11-17 · (unattended) Stage 2 cuts `docs.check.mjs`'s skill assertions to the new skills; its README, hook and field-guide assertions stay until stages 3–4 change those files. The hook's working rules still name `fix` and `review` until stage 3 rewrites them. Why: keeps the suite green at every stage close.
- 2026-11-17 · (unattended) `charter` drops backfilling coverage from shipped plans and the fine-grained re-chart cases (restored IDs, ID clashes, moved PRD sections): kept are PRD to roadmap, the ledger, re-charting without losing history, and milestone close on evidence. Why: the word budget, and eVelo was charted from the start.
- 2026-11-17 · (unattended) "Short" is measured: the six skills at most 5,000 words together, none over 1,500. Why: about a third of 0.18.1's 14,193, and a number a docs check can hold.
- 2026-11-17 · Scale: 4 stages, one release, no PRD; no signal fired, one plan.
- 2026-11-17 · Stage 3's risk is secrets: it rewrites the hook around the secret guard, so it gets a security review (`/security-review`, or `jbit:review` while 0.18.1 is the installed version).

## Open questions
- At a plan's last stage, `stage` sets `## Now` to "All stages done", so the committed plan keeps the ticked stage line but not its ticked checks; the checks live on in the stage's evidence report (seen in stage 2's end-to-end run). Same as 0.18.1; left as is unless the user wants the checks kept — for the user.
- `plugins/jbit/evals-ablation/` (untracked) holds the ablation's case copies and raw results. Delete it once the user has looked, or after stage 4's re-run — for the user.
- Until 1.0.0 is reinstalled from the local marketplace, this session runs the installed 0.18.1 hook and its commit gate. That's fine for this plan, but stage 4 says to reinstall before re-running the evals.
