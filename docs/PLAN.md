# JBIT plan

## Goal
Let the user drive JBIT in plain words, and make autopilot see the plan through by default, released as 0.13.0. Autopilot the user arms with a command — a typed `/jbit:autopilot`, or a message that opens with "JBIT" and holds nothing but command words ("JBIT autopilot lean", "JBIT, just build it. Autopilot, lean.") — runs unattended: it builds risky stages and settles open decisions itself, logging each as `(unattended)`. `outward` still has to be said to let push, publish and deploy through, and `attended` brings back the old stops. The level holds until the user's next command or a new plan Goal. Plain words without the name ("just build it", "take it from here") start autopilot attended, or release a held risky stage; autopilot armed any other way (Claude starting the skill, a Mode line) runs attended too, so only the user's own command lifts a hold. A message opening with the name, in any case and with commas or spaces ("JBIT autopilot", "JBit, approve", "jbit plan"), works as the matching `/jbit:*` command. Talk about autopilot, questions, pasted text with anything else in it, a plugin's prompt, the Skill tool's args or a file arms nothing. Done means the hook, skills, docs and evals match, the suite and validate are green, a headless run shows the hero's command arming the run, and it's committed on main.

## Open questions
- Sixth stage 1 review, deferred: the plain approval reader accepts "just build it — later", "just build it - after lunch" and "just build it, after lunch", while "JBIT approve — after lunch" doesn't; align the two readers. And a rejected `$.state.set` passes the prompt on, so a lowering command ("JBIT autopilot attended" over outward) could be dropped silently; the hook's guards share this `.catch(next)` pattern — fail closed on state-write errors across the hook.
- The hook spots a new plan only by its Goal text, so a plan Claude rewrites while keeping the Goal line word for word keeps an unattended level (third stage 1 review, weaker case). Keying the run on the Goal plus the stage list, or on the plan file's first commit, would close it.
- The CI-host risk grows with this plan: in a host that turns issue text into prompts (`sdk` origin), plain words like "autopilot unattended outward" in an issue would arm a run that lifts every hold and allows push — previously it needed the slash command at the start. Requiring a `composer`/`bridge` origin for plain-words arming (keeping the typed command for headless runs) would close it; for the user.
- Skill and hook text still says `jbit` in lowercase in some prose ("Most of jbit is for work…", "the jbit hook"), where the naming decision says `JBIT`; the stage 1 rename kept the original's case. A wording pass over `plugins/jbit/skills/` and the hook messages — keel:fix-sized, but it touches text Claude follows (stage 2 builder).
- `claude plugin validate .` warns that the marketplace has no top-level `description` (pre-existing; stage 2 builder).
- After the build, for the user: push; move `~/repos/keel` to `~/repos/jbit`; remove the `keel-local` marketplace, add the folder as `jbit-local`, `/plugin install jbit@jbit-local`, uninstall `keel`; and a `Plan:` commit in eVelo-v2, Heel and ToDo updating `keel:*` mentions in their plans (cosmetic: the hook injects the current names).
- In an unattended `outward` run, migrating or deleting real data and spending money still pause (the skill text); only push, publish, deploy and sending data out open. Decided by the stage 2 builder, in line with the Goal.
- Stage 1 review, deferred: `sdk` counts as a user origin, so in a CI host that turns issue text into prompts, text opening with `/keel:autopilot unattended outward` arms a run that lifts every hold and allows push. That makes the known `sdk` approval question larger. Requiring `composer`/`bridge` for `outward` would also block headless runs the user starts themselves, so it's a call for the user.
- `long pathological lines parse in well under 100 ms` failed at 300 ms twice in the stage 1 reviewer's runs and passed in verify's: it's timing-sensitive under load.
- 18 other eval scaffolds set the git author only for their own commit (`git -c user.name=eval …`), so on a machine with no global git identity the agent can't commit and any commit grader fails; the two quick-fix scaffolds now set a repo-local author (stage 1). Apply the same to the rest in a later plan.
- Deferred from stage 1 review: no eval covers the bar's other misses (auth, secrets, a dependency bump, CI config, rendering user content), a fix asked mid-stage or under a held or autopilot stage, or the one-line announcement under an open plan; `quick-fix-risky` covers money only.
- Deferred, pre-existing (stage 1 review): `parsePlan` takes the first heading containing "stage" as the checklist, so a heading like `## Stage fixes` above `## Stages` would be read instead; `## Fixes` doesn't trigger it. And keel:fix says to create `## Fixes` after `## Stages`, which is unclear for a plan without one.
- On this machine the eval tool's sandbox makes the scaffold's `.git` read-only, so any case that commits fails in both arms (`quick-fix` scores 0.4 with and without keel); such cases are proven by a headless run graded by hand. It also needs bubblewrap and socat on Linux, and refuses a credential store with a symlink in it (`~/.docker/contexts` under Docker Desktop on WSL) — worth a line in the README's eval section. — the user; blocks nothing.
- In evidence, prose with a header name, a colon and a 16+ character word holding a digit (`Cookie: set by middleware_handler_v2`) is flagged: the narrow false positive left by the credential-run rule, since an unquoted value runs to the end of the line (stage 2 re-verify). Base64 values split by `/` into pieces under 16 characters, and values with letters only, are missed.
- Stage 2 review, deferred: the evidence header rule reads one line at a time, so pretty-printed HAR (name and value on separate lines), headers split by `\` continuations and percent-encoded headers aren't caught. Custom auth headers (`X-Api-Key`, `X-Auth-Token`) aren't covered. A file renamed into `docs/evidence/` isn't scanned, since a rename adds no lines (which also keeps archiving from being refused). The `<…>` placeholder exemption is shape-only, so a real token wrapped in angle brackets passes. Pre-existing: the guard doesn't see index changes from `git apply --cached`, `stash pop`, `checkout <ref> -- path` or `git mv` earlier on the line, merges, or commits run from scripts; and `keel:allow-secret` is a substring anywhere on the line that exempts every pattern on it.
- Armed state doesn't survive `claude --resume` or `--fork-session`: the resumed process starts unarmed, so a plan paused on a risky stage isn't held there until autopilot is armed again (stage 1 re-verify, `docs/plans/2026-11-09-explicit-approval-secret-formats/evidence/stage-1/headless-paused.txt` lines 191–237). It matches the standing rule that autopilot is armed per session; carrying the armed state across a resume is a design change for the user to weigh.
- Stage 1 security review, deferred (pre-existing): the hold is keyed on the `## Now` stage line, so an approved line left in place while the next risky stage is built still counts as approved. Key it on stage number plus risk words? The risk line and Mode line are editable while held (already noted for project hold words). Bash writes (`cat >`, `sed -i`, `git apply`), MCP file tools and subagents' Bash aren't held. The plan-path exemption matches by case-insensitive suffix, so `src/x/docs/PLAN.md` is exempt.
- Stage 1 security review, deferred: `sdk` counts as a user origin, so in a CI host that turns issue text into prompts, whoever writes that text can approve. `composer` also covers text a plugin filled or the engine suggested. Keel clears before `next(e)`, so a prompt a later hook drops still clears. The held notice puts the agent-written stage line in an OS notification with no length cap.
- An approval isn't tied to the question it answers: while paused on a risky stage, a "yes" to any question Claude asked releases the stage. The autopilot skill tells Claude to ask only the approval question while paused on a risky stage; binding the approval to the hold the hook announced is a later design change.
- Committed screenshots get no secret scan (the guard skips binary files); the docs state the limit and review should look at committed images. A guard for images is out of scope here — the user decides whether it's worth a later plan.
- No eval covers masking yet (a case whose output holds a fake DB URL and email, graded for `[masked]`) — deferred from the last plan's stage 1 review; worth adding in a later plan.
- A `wide` (or `Mode: autopilot`) line that arrives mid-session from git — a checkout or pull of someone else's branch, or a plan that couldn't be read at the session's first look — counts as a change and is honoured without asking; the Mode line already behaves this way. Closing it (move the baseline when the line matches the plan at HEAD, or count only edits made in the user's turn) is a design change for the user to weigh — found in stage 1 review.
- With two Agents lines in `## Now`, only the first is read, so restamping the second does nothing (fails safe, but confusing); and an Agents line past `## Now`'s 40-line cap is parsed but not shown to Claude. Both minor — stage 1 review.
- The `lean` cap counts only `pending`, `running` and `waiting` agents: an `idle` teammate isn't counted (a message can wake it beside a second agent), nor are a SendMessage that resumes a finished agent or a Workflow's fan-out; and agents another plugin spawned, or a dead teammate pane still marked running, count as busy and can stall a `lean` session. The `agent.spawn` event may be a sturdier place for the cap — stage 3 review, deferred. Also deferred from its re-review: when two parallel calls are both refused (the second because the first held the slot, the first further down), the second's "one is still running" is untrue — harmless, Claude can retry.

- A planted stamp the hook reads as date-only (`confirmed 2026-11-08 at 23:59`) could be confirmed by a rewrite that drops the `at`, if the session runs past that minute; it needs a reformat the skills forbid — stage 2 re-review, deferred.
- Deferred from stage 2 review: the scale-check evals are single-turn, so "not asked again" and "re-asked on a stronger signal" have no eval (an arm with a planted logged answer, and one on the next-plan path); worth adding with stage 6's eval list.
