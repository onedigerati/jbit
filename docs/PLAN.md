# JBIT plan

## Goal
Make JBIT runs cheaper without making them less careful, aimed at where the tokens go: in eVelo since 2026-11-13, research agents were about 47% of spend and builders about 30%, 95% of all spend was on Opus, and the costliest agents ran 150–230 turns at 300–400k context, so cache reads (about 60% of spend) dominate; verify and review together were about 12%. Three changes: a `research` role on the Models line, so research agents can run on a cheaper model; brief rules that keep every delegated agent small (batch sizing, narrow reading, short handoff reports); and a per-user Models default kept in JBIT's own store, set once by the user's command and used in every repo, with a `CLAUDE.md` default honoured only once the user confirms it in the session. Done when, under `Models: build sonnet/medium · research sonnet/high · review opus/high`, a headless autopilot run starts its research agent on Sonnet at high and its builder on Sonnet at medium; a research fan-out of nine items goes to agents of at most a few items each; `JBIT models … — my default` in one repo starts a new plan's Models line in another; and 0.18.0 ships with docs and evals.

## Decisions
- 2026-11-16 · Plan from the eVelo token-spend analysis (57 sessions, 276 subagent transcripts, cost weighted cache read 0.1×, cache write 2×, output 5×): model routing and agent size are the levers worth building first; lighter verify and review (`Checks: light`) wait until this plan's savings are measured — the user's pick in this session ("A and B", then "include" the per-user default).
- 2026-11-16 · Replaces the standing decision (2026-11-15) that research agents are no role: research becomes a role, `research`, written `model/effort` like the others; a call naming neither still runs as the session, so Explore agents and a forgetful call are unchanged — research was about half of eVelo's recent spend and always ran on the session's model.
- 2026-11-16 · Spend controls stay on separate lines that don't overlap: the Models line alone sets model and effort, the Agents line alone sets how many run at once; no preset word sets models, since a changed Models line needs the user's own words naming its settings — the user agreed in this session.
- 2026-11-16 · The per-user default lives in the hook's `$.store` (kept between sessions, per user, outside every repo), written only by the user's own `JBIT models … — my default` command; no research: the store is in Claude Code's own plugin types.
- 2026-11-16 · Stage 3 replaces the standing decision that a plan line matching the `CLAUDE.md` default counts as confirmed (2026-11-15), striking it then: a `CLAUDE.md` default is honoured only once the user confirms it in the session, closing the open question that a cloned repo's committed default can raise spend unasked.
- 2026-11-16 · Agent-size rules are brief text, not a hook: the hook can't shorten a tool's output or end an agent at a context size, and the rules cost nothing when work is small.
- 2026-11-16 · Agents: lean, carried from the last plan.
- 2026-11-16 · (unattended) Stage 1 review fix: a changed Models line needs each added or changed role named as a word, besides its values — without it, adding `research` with values already on the line was confirmed by a prompt that never said "research"; tying each value to its role is deferred as a larger change to the confirmation rule.
- 2026-11-16 · (unattended) Stage 3: the user's own default fills each role the plan's line leaves out, as the precedence says, so `JBIT models none` or `<role> none` holds for the session only; the notice says so and names `JBIT models clear my default` — keeping the planned precedence over a sticky "none", which the store can't tell apart from no line.
- 2026-11-16 · (unattended) Stage 3: `… — my default` merges the named roles into the stored default rather than replacing it, and saves nothing when the store can't be read first, so a partial save never drops stored roles unseen — review finding.
- 2026-11-16 · (unattended) Stage 4 risk line corrected to docs only: the diff touches skill text, READMEs, field guide, eval cases and the version, no hook code, so no security review.
- 2026-11-16 · (unattended) Stage 4: `jbit:plan`'s description says to load it before any research for a plan — a headless run researched nine items inline before loading it, so the batch rule never applied; skill text, not a hook, as the agent-size decision says.
- 2026-11-16 · (unattended) Stage 4: the 0.18.0 changelog is the plan's `## Shipped` line, as for 0.17.0; the repo keeps no changelog file.
- 2026-11-16 · Scale: 4 stages, one release; no signal fired, one plan.
