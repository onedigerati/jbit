Plugin skills:
  autopilot - Take over an approved plan as its project manager and see it through — run every remaining stage through build, verify, review and commit without stopping between stages, keep the plan current, and come back to the user only when something is stuck or theirs to decide. The user's own command, a typed `/jbit:autopilot` or a message opening with "JBIT" made of command words ("JBIT autopilot lean", "JBIT, just build it. Autopilot, lean."), runs it unattended, deciding and logging judgment calls itself; `attended` keeps the stops for risky stages and open decisions. Use when the user approves a plan and says to run it, "just build it", take it from here, see it through, or put it on autopilot, and when a message opens with "JBIT autopilot" or "JBIT, just build it" (any case, after a space, comma or colon), as `/jbit:autopilot` does. While autopilot holds a risky stage, "just build it" is the user's approval of it, not a new run.
  fix - Make a small, low-risk change without a stage — a style or copy tweak, a display bug, a docs or comment edit — built in the main session, checked in proportion to its risk, logged as one line in the plan and committed on its own. Use when the request fits the quick-fix bar below, when jbit:plan or jbit:autopilot recommends it and the user agrees, or when the user asks for a quick fix. Anything that misses the bar goes to jbit:plan. Also when a message opens with "JBIT fix" (any case, after a space, comma or colon, as in "JBit, fix"), which works as `/jbit:fix`.
  resume - Pick a project back up after a break, a restart or a context summary — read the plan, the commits since the last stage, and uncommitted work, then say where things stand and what's next. Use at the start of a session on an existing project, after compaction, or when the user asks where we are. Also when a message opens with "JBIT resume" (any case, after a space, comma or colon, as in "JBit, resume"), which works as `/jbit:resume`.
  review - Fresh-eyes review of recent work by an agent that didn't write it — correctness against the plan's intent, edge cases, tests, and a security pass when the stage touches user input, auth, money, personal data, secrets or external services. Findings are verified and triaged into fix, defer or reject. Use at the end of risky stages and milestones, or when asked to review. Also when a message opens with "JBIT review" (any case, after a space, comma or colon, as in "JBit, review"), which works as `/jbit:review`.
  stage - Run the next stage of the project plan end to end — scope it, build it (fanning independent parts out to subagents), test, verify against the running product, review, update the plan, commit, and stop for the user's review. Use when the user says to start, continue or "go" on planned work, or names a stage to build. Also when a message opens with "JBIT stage" (any case, after a space, comma or colon, as in "JBit, stage"), which works as `/jbit:stage`.
  verify - Verify work against the running product and the project's own checks — type check, lint, tests, build, a dependency audit, then each acceptance check proven by driving the real app (screenshots, scripted clicks, requests, CLI runs), with a per-check report; when a plan stage is verified, the report and the output behind it are saved to docs/evidence/stage-<n>/. Use before calling any stage done (a `jbit:fix` change gets the lighter check in its own skill), when asked to verify, test or check something works, or when unsure whether a change actually works. Also when a message opens with "JBIT verify" (any case, after a space, comma or colon, as in "JBit, verify"), which works as `/jbit:verify`.
