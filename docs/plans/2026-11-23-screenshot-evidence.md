# JBIT plan

## Goal
Make screenshots first-class evidence for UI and UX work, on every host JBIT ships to. The plugin carries a small capture script in the verify skill (`plugins/jbit/skills/verify/scripts/capture.mjs`). It gets Playwright from the project first, then the host's own browser tools, then a pinned install (`playwright-core@1.65.0` and Chromium's headless shell, about 130 MB) into a JBIT cache outside the repo, made only after the user says yes once per project. There is no bundled MCP server. A plan's screenshot proof names the state, widths and themes; `jbit:stage` captures "before" shots before building, and `jbit:verify` captures "after" shots. The fresh verifier looks at each one and writes a line on what it shows. The commit gate refuses to close a stage whose report links an image that isn't there. Re-runs at the last stage compare screenshots with the saved ones. Screenshots stay gitignored by default, and `jbit:plan` asks once, for a plan with UI work, whether this repo commits them. Done when the Claude Code plugin and the generated Copilot and Codex packages carry all of this, and a headless run on a small web app closes a UI stage with before and after screenshots, described rows and a refused close for a missing image. The suite, docs check, host tests and validate stay green throughout. Pushing waits for the user.

## Decisions
- 2026-11-23 · Screenshots come from a capture script shipped with the plugin, not a bundled MCP server or the host's browser tools alone; Playwright comes from the project, then host browser tools, then a pinned cache install after the user's yes once per project, logged as a decision in that project's plan. Screenshot proofs name state, widths and themes; stage takes before shots, verify after shots; the fresh verifier writes one line per screenshot on what it shows; the gate refuses a missing linked image; last-stage re-runs compare screenshots. Screenshots stay gitignored by default and plan asks once per UI plan whether to commit them — the user's choice ("go with recommendations"), 2026-11-23.
- 2026-11-23 · (pm) The 2026-11-20 rule that `plugins/jbit/` stays byte-identical to `c087d40` ended with that plan; this plan changes the plugin on purpose, and the generated packages are rebuilt from it. Why: the goal is a plugin feature, and the drift check keeps the packages in step.
- 2026-11-23 · (pm) The image check sits in the hook's evidence gate before the commit and reads the working tree, not the after-commit check. Why: images are gitignored by default, so the commit never holds them, and `git show` of a landed report would fail every local image (survey).
- 2026-11-23 · (pm) The script imports Playwright dynamically from a resolved path, never by bare name. Why: the host build refuses a copied script with a bare package import.
- 2026-11-23 · (pm) The script's tests run with `node --test` beside `docs.check.mjs`. Why: `claude plugin test` runs in a sandbox with no file access, so it can't run a browser.
- 2026-11-23 · (pm) The script lives in the verify skill's own `scripts/` folder and finds its own location; skills point at it as `${CLAUDE_SKILL_DIR}/scripts/capture.mjs` (stage and fix as `${CLAUDE_PLUGIN_ROOT}/skills/verify/scripts/capture.mjs`), and `hosts/build.mjs` rewrites those to skill-relative paths for Copilot and Codex, with a test that no `${CLAUDE_` text is left. Why: Claude Code substitutes those variables in skill text but doesn't set them in the model's shell; Codex resolves paths against the skill's folder; Copilot is unproven and gets a live check in stage 3 ([skill-script-paths-2026-11.md](../research/skill-script-paths-2026-11.md)).
- 2026-11-23 · (pm) Pinned Playwright is `playwright-core@1.65.0` (18 days old; 1.65.1 is 10) with `install --only-shell chromium` into `PLAYWRIGHT_BROWSERS_PATH` under the JBIT cache. Why: the core package is all a script needs, and the shell is the smallest browser that launches headless ([playwright-capture-2026-11.md](../research/playwright-capture-2026-11.md)).
- 2026-11-23 · (pm) Compare draws both PNGs on a canvas in the same headless browser and counts differing pixels, rather than installing pixelmatch and pngjs or using Playwright's internal comparator. Why: it adds no dependency beyond the browser the script already has, and the internal comparator is unsupported ([playwright-capture-2026-11.md](../research/playwright-capture-2026-11.md)).
- 2026-11-23 · Agents: wide — the user's choice, confirmed in this session (2026-11-23 11:54), with autopilot.
- 2026-11-23 · (pm) This repo's own capture tests use a Playwright cache in the session scratchpad (`JBIT_CAPTURE_CACHE`), installed with the script's own `install`, and browser tests report as skipped with the reason when none is found; verify counts a skip as a fail. Why: the tests need a real browser, and the per-project yes the script asks for is a product rule for users' projects, which this development download (approved with the plan) doesn't replace.
- 2026-11-23 · (pm) Stage 1 review: both fix-now bugs (symlink entry, Windows drive paths) fixed, and five deferrable findings taken now because each was small and lands before skills depend on the script: project-only Playwright lookup plus `@playwright/test`, masked credentials and query values in the console log, a sudo hint that never runs project code, `--ignore-scripts`, per-shot errors keeping the log, and compare failing on missing after-shots. Left: no download hash beyond npm's own check (nit), and symlinks inside `--out` (the caller picks `--out`). The install-needs-yes rule goes into the skill text in stage 2 ([report](2026-11-23-screenshot-evidence/evidence/stage-1/report.md)).
- 2026-11-23 · (pm) Lookup order refined: project's Playwright, then the JBIT cache if it's already installed, then the host's browser tools, then asking about `install`. Why: the script can't see host tools, and an installed cache downloads nothing; the user's yes still guards the only download. The cache is per user, so one yes serves every project on that machine.
- 2026-11-23 · (pm) Stage 2 review: fixed the planted-script path (a `<verify skill folder>` placeholder with its rule beside the first use), the install yes and commit-screenshots opt-in counting only the user's own words, Windows drive links, links in code, reference-style and `<img>` links, the image-link cap and a throwing exists check. Left: a symlink in the stage folder counts as present (existence only, never read), and a folder named `x.png` passes ([report](2026-11-23-screenshot-evidence/evidence/stage-2/report.md)).
- 2026-11-23 · (pm) Stage 3 live runs, fix round 1: (a) a commit on the same command line as a change under `docs/evidence/` is refused like the plan-file rule, since the gate checks before the line runs (Claude run 2 landed a close after `rm … && git commit`); (b) the Codex hook lets exactly one shape through its `$CODEX_HOME` guard, `node <plugin cache>/jbit/<v>/skills/verify/scripts/capture.mjs …` with no chaining and no output under `$CODEX_HOME`, since Codex installs plugins there and every capture was refused; (c) verify runs the capture script only from the plugin, never one found in the project, and says so when it's denied (a headless Copilot run, denied the plugin folder, ran a planted project script); (d) Copilot's gap says headless runs need `--add-dir <plugin folder>`. Why: each came from a live run in [stage 3 evidence](2026-11-23-screenshot-evidence/evidence/stage-3/).
- 2026-11-23 · (pm) Stage 3 review, fix round 2: the Codex exception checks the capture cache's location on every call (an `install` placed after a flag slipped past a check of the second word only); the same-line evidence rule refuses conservatively (any `git clean`, `git stash -u`, `git reset --hard`, pathless `git restore`/`checkout`, deletes of a parent folder, globs, braces, variables, `xargs rm`, redirects on every command), accepting a few false refusals such as `cp -r docs /tmp/bak && git commit`; gap lines say only what the live runs showed. Why: each was confirmed by a reviewer, and a refusal costs one extra command while a miss lets a stage close on missing evidence.
- 2026-11-23 · (pm) Left, logged rather than fixed: on Codex the allowed capture command loads Playwright from the project's `node_modules`, so a planted package can still write under `$CODEX_HOME` — the same class as any `node script.js`, already in the `codex-home-guard` gap; the Codex exception refuses shapes models sometimes try first (`2>&1`, a shell variable for the path), which costs a retry; `git checkout <branch>` and `git switch` on a commit line aren't refused.
- 2026-11-23 · (pm) Scale: three stages, one plan; no charter. Why: one feature, well under eight stages.
- 2026-11-23 · (pm) Risk: stage 1 runs a browser against a URL and may point at a download (user input, external services); stage 2 changes the commit gate (it reads report text, user input); stage 3 installs packages and runs live hosts (external services). All three get the security pass.

## Open questions
- Screenshot evidence, from this plan's reviews, for the user:
  - A python heredoc that edits only `docs/PLAN.md`, on the same line as a commit, is now refused by the cautious evidence rule (it names `docs`); harmless, but one extra command ([stage 3 report](2026-11-23-screenshot-evidence/evidence/stage-3/report.md)).
  - The plan-file same-line rule applies only under autopilot; outside it, a check after the commit catches a stage closed that way. Extending it is a scope call.
  - On Codex, screenshots need the sandbox off for the capture command, and the allowed command still loads Playwright from the project's `node_modules`.
  - A symlink or a folder named like an image in the stage folder counts as a present screenshot.
- Carried from [Copilot and Codex hosts](2026-11-20-copilot-codex-hosts.md), all for the user:
  - What 2.0.0 users lose from 1.x (role agents and their overrides, the `CLAUDE.md` fan-out limit, the handoff overflow rule and `review.md`, the verifier `report.md` workaround); carrying any of it into 2.0.x is for a later plan.
  - Single-run eval drops between 0.18.1 and 1.0.0 (charter-prd, regression-caught, research-spike) were never re-run with more runs.
  - The secret guard can't see commits made through config-file git aliases (`git ci`), `git $x`, or scripts.
  - `hosts/parity/claude.test.ts` sends a prompt before composing it; settle Claude Code's real order when a scenario judges an arming prompt's context.
  - On Claude Code, the commit guard steps aside when git fails (huge diff, timeout); Copilot's shim fails closed ([review](2026-11-20-copilot-codex-hosts/evidence/stage-2/review.md)).
  - The commit gate trusts any tick it has seen, so a check can be ticked in one commit and the stage closed in the next ([review](2026-11-20-copilot-codex-hosts/evidence/stage-4/review.md)).
  - Codex: `~/.CODEX/…` on a case-insensitive file system gets past the `$CODEX_HOME` guard; a missing `node` or failed import likely fails open; the guard is best-effort against shell obfuscation ([review](2026-11-20-copilot-codex-hosts/evidence/stage-6/review.md)).
  - In a held stage, a shell write gets through on every host; the hold covers edit tools and Agent, not Bash ([report](2026-11-20-copilot-codex-hosts/evidence/stage-6/report.md)).
  - A model can write "User approved stage <n>" into the plan's text; the hold doesn't read it ([review](2026-11-20-copilot-codex-hosts/evidence/stage-7/review.md)).
  - `plugins/jbit/evals-ablation/` and the root `CLAUDE.md` are untracked; commit or drop.
